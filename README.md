# Azure Infrastructure Provisioner

**Production-grade, interactive Bash-driven Terraform automation for Azure.**

```
┌─────────────────────────────────────────────────────────────┐
│              Azure Infra Provisioner                        │
│                                                             │
│   User ──► Bash CLI ──► Validate ──► Pre-check Azure        │
│                                        │                    │
│                              .tfvars ──► Terraform          │
│                                            │                │
│                                       Azure Cloud           │
│                                       ├── Resource Group    │
│                                       ├── VNet + Subnets    │
│                                       ├── NSG (SSH/HTTP/S)  │
│                                       ├── VMs (N)           │
│                                       ├── Storage Account   │
│                                       ├── Key Vault         │
│                                       └── Load Balancer     │
│                                            │                │
│                              Verify ◄──────┘                │
│                                │                            │
│                           CSV Report                        │
└─────────────────────────────────────────────────────────────┘
```

## Features

- **Interactive CLI** — guided prompts with input validation at every step
- **Pre-apply validation** — checks VM SKU availability, Key Vault name collisions, and Storage Account name uniqueness *before* creating anything
- **Auto-rollback** — on partial terraform apply failure, offers to automatically destroy orphaned resources
- **Post-apply verification** — polls Azure to confirm all resources reach `Succeeded` state and VMs are `Running`
- **Detailed CSV export** — generates a 30-column business-grade resource report with IPs, SKUs, disk info, tags, and resource IDs
- **Full audit logging** — every run is logged to `logs/` with timestamps
- **Ctrl+C safe** — trap handlers prevent orphaned state on interruption
- **Production-grade validation** — CIDR format + overlap detection, subnet-within-VNet checks, Azure password complexity rules, blocked username detection

## Architecture

```
azure-infra-provisioner/
├── main.tf                  # Root module - composes all child modules
├── variables.tf             # All input variable declarations with validation
├── outputs.tf               # Output values after provisioning
├── providers.tf             # Azure provider configuration (AzureRM ~> 3.80)
├── terraform.tfvars         # (Auto-generated by Bash - DO NOT EDIT)
├── modules/
│   ├── resource_group/      # Azure Resource Group
│   ├── virtual_network/     # VNet with optional custom DNS
│   ├── subnet/              # Subnets (1-10, overlap-validated)
│   ├── nsg/                 # Network Security Groups + subnet association
│   ├── public_ip/           # Public IPs (Standard SKU, static)
│   ├── nic/                 # NICs (round-robin across subnets)
│   ├── virtual_machine/     # Linux VMs (SSH key or password auth)
│   ├── storage_account/     # Storage (HTTPS-only, TLS 1.2, soft delete)
│   ├── key_vault/           # Key Vault (env-based retention, network ACLs)
│   └── load_balancer/       # Load Balancer (HTTP probe + rule)
├── scripts/
│   ├── provision.sh         # Main interactive CLI
│   ├── validate.sh          # Input validation functions
│   ├── pre_validate.sh      # Azure availability pre-checks
│   ├── post_apply.sh        # Resource verification + CSV export
│   └── destroy.sh           # Teardown (double confirm for prod)
├── environments/            # Saved configuration backups per run
├── logs/                    # Audit logs per run
└── reports/                 # Generated CSV resource reports
```

## Quick Start

```bash
# 1. Enter the project
cd azure-infra-provisioner

# 2. Login to Azure
az login

# 3. Run the provisioner
chmod +x scripts/*.sh
./scripts/provision.sh

# 4. Follow the interactive prompts
```

## Execution Flow

```
1. Pre-flight checks     → Terraform + Azure CLI installed? Logged in?
2. Collect global config  → Project name, environment, region, tags
3. Collect network config → VNet CIDR, subnets (validated, no overlaps)
4. Collect VM config      → Per-VM: size, OS, disk, auth, public IP
5. Collect optional       → Storage Account, Key Vault, Load Balancer
6. Generate tfvars        → Write config file + backup
7. Review summary         → Full configuration displayed
8. Pre-validation         → Check Azure: SKU availability, name collisions
9. Terraform plan         → Dry run
10. Terraform apply       → Create resources (with rollback on failure)
11. Post-apply verify     → Poll Azure until all resources Succeeded
12. CSV report            → Detailed resource export to reports/
```

## Validation Checks

| Input | Validation |
|---|---|
| Project name | 3-24 chars, lowercase alphanumeric + hyphens, no leading/trailing hyphen |
| Region | Checked against 30+ valid Azure regions |
| VM size | Must match `Standard_*` format, checked against common sizes list |
| VNet CIDR | Format validated, octets 0-255, mask /8 to /30 |
| Subnet CIDR | Format + within VNet + no overlap with other subnets |
| Tag keys | No spaces, no special chars, max 128 chars |
| Admin password | 12-123 chars, 3-of-4 complexity (upper/lower/digit/special), confirmed |
| Admin username | Not in Azure blocked list (admin, root, test, etc.) |

## Pre-Apply Checks (Azure API)

| Check | What it catches |
|---|---|
| `az vm list-skus` | SKU not available in region (capacity restrictions) |
| `az keyvault list` + `list-deleted` | Active or soft-deleted vault name collision |
| `az storage account check-name` | Storage account name already taken globally |

All three run in ~5 seconds before any resources are created.

## Security Hardening

- Storage accounts enforce HTTPS-only with TLS 1.2 minimum
- Blob and container soft-delete enabled (7-day retention)
- Key Vault soft-delete: 30 days (dev/staging), 90 days (prod)
- Key Vault network ACLs configured (bypass for Azure services)
- NSG rules are opt-in (SSH default yes, HTTP/HTTPS default no)
- Passwords never logged to screen (read -s), validated against Azure complexity rules
- terraform.tfvars gitignored (contains sensitive data)
- Public IPs use Standard SKU with static allocation

## Destroying Resources

```bash
./scripts/destroy.sh
```

- Requires typing the project name to confirm
- Production environments require typing `DESTROY PROD` as second confirmation
- Falls back to `az group delete` if terraform destroy fails
- Handles missing tfvars gracefully

## Requirements

- Terraform >= 1.5
- Azure CLI >= 2.50
- Bash >= 4.0
- An active Azure subscription
- Python 3 (for post-apply CSV generation)
